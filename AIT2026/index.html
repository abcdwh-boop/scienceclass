01 기획하기

구체화 하기 (PDR 작성해보기)

앱의 목적, 사용자, 기능, 데이터 처리 방식을 정리합니다. 필요한 사항을 PRD(제품 요구사항 문서)로 정리하면 이후 수정 과정에서도 기준으로 활용할 수 있습니다.

1

📄 PRD란?

(Product Requirements Document: 제품 요구사항 문서) 만들고자 하는 결과물에 대해서 작성하는 문서입니다. 앱의 제작 목적, 사용자, 주요 기능, 화면과 동작 규칙을 정리합니다.

2

🤔 왜 작성하는가?

AI에 전달할 요구사항을 명확히 하고, 기능을 수정하거나 다른 제작 도구로 옮길 때 기준 문서로 사용합니다.

필수는 아닙니다. 아주 간단한 형태의 앱을 만들 때에는 따로 작성하지 않고, 직접 AI에게 명령할 수도 있어요.

하지만 , 복잡한 구조의 앱을 만들때에는 많은 부분들에서 확정되어야 효율적으로 앱 제작이 가능합니다.

✍️ 연습해 보기

'PRD 작성 도우미' 로 PRD가 어떻게 생겼는지 직접 만들어볼 수 있어요.
규격이 정해져있는 것은 아닙니다. 기본적으로 들어갈 내용들에 대한 참고사항으로 생각하시면 됩니다.

3

💬 PRD 작성 : AI와 대화하며 함께 작성할 수 있습니다. [추천!]

  • 복잡한 구조의 앱을 제작할 때에는, 제작자가 미처 생각하지 못하는 부분들이 있을 수 있어서 앱을 제작하기 전에 AI와 대화하며 구체적인 PRD를 작성할 수 있습니다.
  • AI에게 제작 의도와 목적, 사용자, 필요한 기능 등을 설명합니다.
  • 결정하지 못한 부분, 고민인 부분도 함께 전달하고 대안을 요청합니다.
  • 대화를 바탕으로 PRD를 정리해달라고 한 뒤 파일로 보관합니다.
실습을 마치고 내 앱을 만들 때는 각 실습의 마지막 장 도움자료: 내 앱 기획하기에서 도구에 맞는 PRD 요청문을 만들 수 있어요.

02 방식 선택

어떤 방식으로 만들 것인가?

아래 질문에 답해보면서 선생님이 만드실 앱에 적합한 방식을 확인해보세요.

📒 내가 고른 답

    답을 누르면 그 질문으로 돌아가요. 추천은 초기 설계 참고용이니 실제 인원·요청 빈도·학교 계정 정책으로 꼭 시험해 보세요.

    💗
    03 AI 윤리 · 1/4 만들기 전에 꼭!

    학생을 위한 앱, 사람을 먼저 생각해요

    교육부 「교육분야 인공지능 윤리원칙」(2022)의 정신을 교사 앱 제작 상황에 맞게 여섯 가지로 정리했습니다.

    🙋

    학생이 주인공

    앱은 학생의 생각을 대신하지 않고 돕습니다. 정답을 바로 주기보다 스스로 따져 볼 기회를 남겨요.

    🔍

    최종 확인은 교사가

    AI가 만든 코드·설명·피드백은 교사가 확인한 뒤 씁니다. 개념 오류와 평가 판단의 책임은 사람에게 있어요.

    🤝

    모두에게 공정하게

    예시와 피드백에 성별·지역·문화 고정관념이 없는지 봅니다. 기기 사양이나 시력, 읽기 속도가 달라도 쓸 수 있게 만들어요.

    🔐

    데이터는 꼭 필요한 만큼

    실명·연락처 대신 번호나 별칭으로 충분한지 먼저 생각합니다. 모은 데이터는 언제 지울지 정해 둬요.

    💬

    투명하게 알리기

    AI로 만든 앱인지, 앱 안의 AI가 무엇을 하고 입력이 어디로 가는지 학생과 보호자가 알 수 있게 안내합니다.

    ©️

    저작권과 출처

    AI가 만든 이미지·글, 인터넷 자료의 이용 조건을 확인하고 출처를 밝힙니다. 학생 작품을 쓸 때는 동의를 받아요.

    🏛️
    03 AI 윤리 · 2/4 2026년부터 달라진 것

    학생이 쓰는 앱, 이제 학운위 심의를 거쳐요

    교사가 직접 만든 앱도 예외가 아닙니다. 심의는 번거로운 절차가 아니라, 학생 정보를 지키고 앱을 만든 선생님을 지켜 주는 공식 승인입니다.

    📜 초·중등교육법 제29조의2 · 2025년 8월 개정 · 2026년 3월 1일 시행

    학교의 장이 학습지원 소프트웨어를 교육자료로 선정하려면 교육부 장관이 (개인정보보호위원회와 협의해) 정한 기준을 지키고 학교운영위원회 심의를 거쳐야 합니다.

    ✅ 심의 대상 (정규 교육과정에서 쓰는 것 중)

    • 학생 개인정보를 수집·이용·제공 등 처리하는 소프트웨어
    • 교과 성취기준 관련 학습 콘텐츠를 담아, 교육과정 지원 목적으로 개발·보급된 소프트웨어
    • 둘 중 하나만 해당해도 대상이에요.

    ⭕ 대상이 아닌 것

    • 교사가 수업 준비·행정업무에 학생 개인정보 처리 없이 쓰는 도구
    • 방과후 수업, 국가·국제 수준의 일시적 평가
    🧑‍🏫 교사가 만든 앱도 개인정보를 수집·처리하면 심의 대상입니다. 교사가 개발자라면 필수기준 체크리스트와 증빙을 교사가 직접 작성해요.
    1. 1교원 의견 수렴
    2. 2필수기준 충족 확인
    3. 3학운위 상정·심의
    4. 4학교장 최종 확정

    학기 중에 새로 쓰려는 앱도 심의를 거친 뒤에 사용해요. 시기를 놓쳤다면 다음 학운위에 올립니다.

    🔎 내 앱은 심의 대상일까?

    세 가지만 답해 보세요.

    ① 정규 교과 수업에서 학생이 이 앱을 쓰나요?

    ② 학생을 알아볼 수 있는 정보를 받거나 저장하나요?

    실명, 학번, 이메일(구글 로그인 포함), 사진·목소리, 이런 정보와 연결된 학습 기록

    ③ 성취기준 학습 콘텐츠를 담아 여러 학교·교사에게 보급하나요?

    답을 고르면 결과가 나와요.

    근거: 교육부 보도자료 「학교의 안전하고 효과적인 학습지원 소프트웨어 선정을 위한 기준 안내」(2025.12.29.), 「2026학년도 학습지원 소프트웨어 교육자료 선정 학교운영위원회 심의 가이드(안)」(2026.1.). 세부 판단은 학교와 교육청 안내를 따르세요.

    🔐
    03 AI 윤리 · 3/4 내 앱이 갖출 것

    필수기준을 내 앱에 옮기면

    필수기준은 「개인정보 보호법」에서 반드시 지켜야 하는 사항이라, 하나라도 못 갖추면 사용할 수 없습니다. 교사 앱에서는 이렇게 준비해요.

    1
    최소 처리꼭 필요한 정보만, 목적·항목·보유기간을 밝히기

    실명 대신 번호나 별칭으로 되는지 먼저 생각해요. "이 정보가 없으면 수업 활동이 안 되나?"에 답이 '아니요'면 받지 않습니다.

    2
    안전조치접근 권한 관리, 안전한 저장

    시트는 학생에게 공유하지 않고, Firebase는 보안 규칙을 설정합니다. 관리자 비밀번호·API 키를 HTML 안에 쓰지 않아요.

    3
    열람·정정·삭제·처리정지언제든 요구할 수 있는 방법 안내

    "내 기록 보기·지우기" 버튼을 두거나, 요청할 곳(담당 교사)을 앱에 적어 둡니다. 실제로 지울 수 있는지도 시험해요.

    4
    만 14세 미만 보호법정대리인(보호자) 동의 절차

    중학교 1학년은 대부분 만 14세 미만입니다. 보호자 동의서를 미리 받고, 동의하지 않은 학생도 참여할 수 있는 대체 방법을 마련해요.

    5
    처리방침 공개보호책임자, 제3자 제공·위탁 안내

    앱 첫 화면이나 링크로 '개인정보 처리 안내'를 보여 줍니다. 구글·Firebase·AI API처럼 데이터가 거쳐 가는 외부 서비스도 적어요.

    📝 동의를 받을 때 알릴 네 가지

    1. 무엇에 쓰는지 (수집·이용 목적)
    2. 무엇을 받는지 (수집 항목)
    3. 언제까지 갖고 있는지 (보유·이용 기간)
    4. 동의하지 않을 수 있고, 그때 불이익은 무엇인지

    🤖 AI에게 안내문 초안 부탁하기

    내가 만든 수업용 웹앱의 「개인정보 처리 안내문」과 보호자 동의서 초안을 만들어 줘.
- 수집 항목: (예: 학번 끝 두 자리, 학교 Google 계정 이메일, 활동 기록)
- 이용 목적 / 보유 기간: (예: 2026학년도 2학기 과학 수업 활동, 학기 종료 후 삭제)
- 데이터가 저장·전달되는 서비스: (예: Google 스프레드시트)
- 보호책임자(담당 교사)와 열람·정정·삭제 요청 방법 포함
- 만 14세 미만 학생의 보호자 동의란, 동의 거부 시 대체 활동 안내 포함
- 중학생과 보호자가 읽기 쉬운 말로

    03 AI 윤리 · 4/4 직접 열어 보기

    로그인했는데 왜 다 보일까요?

    AI로 뚝딱 만든 '학생 정보 조회' 앱입니다. 아이디·비밀번호를 몰라도 네 단계면 모든 학생 정보가 보여요. 모든 정보는 가상입니다.

    🧪 예시 앱 직접 열기 ↗
    https://우리반-앱.netlify.app/

    🔒 학생 정보 조회

    아이디 10101
    비밀번호 ••••
    로그인

    로그인을 거쳐야만 내 정보가 나오니 안전해 보입니다. 그런데 이 확인은 학생 브라우저 안에서 이뤄져요. 확인하려면 브라우저가 비밀번호 목록과 전체 학생 정보를 미리 받아 와야 합니다.

    1const USERS = [
2  { id: "admin", password: "2026", role: "admin" },
3  { id: "10101", password: "1234", role: "student" },
4  { id: "10102", password: "1234", role: "student" },
…
8const STUDENTS = [
9  { id: "10101", name: "김코딩",
12    grades: { "정보 수행평가": "A", "웹앱 프로젝트": "92점" … },
20    teacherMemo: "프론트엔드 구조 이해가 빠르며…" },

    배포한 파일은 모두 공개 주소가 생깁니다. 관리자 비밀번호와 모든 학생의 성적·교사 메모가 글자 그대로 보여요.

    > STUDENTS
  ▸ (3) [{…}, {…}, {…}]
    0: {id: '10101', name: '김코딩', grades: {…}, teacherMemo: '…'}
    1: {id: '10102', name: '박개발', grades: {…}, teacherMemo: '…'}
    2: {id: '10103', name: '이교사', grades: {…}, teacherMemo: '…'}
> USERS[0]
  ▸ {id: 'admin', password: '2026', role: 'admin', name: '관리자'}

    코드를 읽을 줄 몰라도 됩니다. 변수 이름만 치면 전체 명단이 표로 나와요. 관리자 비밀번호로 로그인하면 관리자 대시보드까지 열립니다.

    사진도 /assets/학번_이름.jpg 주소로 로그인 없이 열립니다. 학번 순서를 알면 다른 학생 사진 주소도 짐작할 수 있어요. 공개 GitHub 저장소라면 폴더째 내려받을 수도 있습니다.

    💗
    우리의 약속: 학생 정보는 앱에 넣지 않아요

    이름·학번·성적·사진 같은 실제 학생 정보로 앱을 만들거나 AI에게 붙여 넣지 않습니다. 연습은 '김코딩'처럼 가상 데이터로 해요.

    실시간 데이터 앱

    여러 기기의 변경 사항 동기화, 로그인, 권한 설정이 필요한 앱을 AI에게 배우며 만들어요.

    • 핵심: 백엔드·인증·실시간 갱신
    • 진행: PRD + 따라하기 요청문으로 AI와 한 단계씩
    • 예시: 아나바다 앱, 창조주의 행성, 감염병 예방 시뮬레이션
    ✅
    05 배포 전 점검

    배포 전에 확인할 사항

    강의 중 제작한 앱을 다른 기기에서 확인하고, 공유 범위와 데이터 처리 조건을 점검합니다. 항목을 눌러 체크해 보세요.

    📱

    기능·화면 확인

    • 버튼과 입력 기능이 정상 작동하는가?
    • 빈 입력 · 잘못된 입력에도 오류 없이 안내되는가?
    • 휴대전화와 다른 브라우저에서도 정상 표시되는가?
    • 새로고침 후 데이터가 의도대로 유지되는가?
    🔒

    공개·데이터 확인

    • 학생 실명 등 불필요한 개인정보가 없는가?
    • 비밀키·비밀번호·관리자 정보가 코드에 포함되지 않았는가?
    • 시트·데이터베이스 읽기와 쓰기 권한을 확인했는가?
    • 공개 URL을 누가 사용할 수 있는지 확인했는가?

    이 항목은 배포 직전 점검용입니다. 개인정보 및 AI 활용에 관한 상세 점검은 07단계에서 확인합니다.

    🚀
    06 배포하기

    완성한 웹앱 배포하기

    배포는 내 파일에 다른 사람도 열 수 있는 주소를 붙이는 일이에요. 내 기기에서만 사용할거라면 배포가 꼭 필요하지 않을수도 있어요.

    하지만 어떤 기기에서든 열어볼 수 있으려면 배포가 필수입니다.

    ⚡ 간단하게 쓰기

    📦

    Netlify (넷리파이) Drop

    완성한 폴더를 끌어다 놓기만 하면 주소가 생겨요. 오늘 수업, 이번 행사처럼 단발성으로 쓸 때 가장 빨라요.

    1. 폴더를 하나 만들어요.
    2. 코드가 적힌 파일(HTML 형식)의 이름을 index.html로 바꾸어 폴더에 넣어요.
    3. Netlify Drop 화면에 폴더째 끌어다 놓기
    4. 웹앱의 주소가 생성됩니다.
    Netlify Drop 열기 ↗

    고칠 때마다 다시 끌어다 놓아야 하고, 파일이 여기저기 흩어지기 쉬워요.

    🌱 계속 고치고, 포트폴리오로 모아 둘 생각이시라면

    🐙
    보관할 장소가 필요해요

    GitHub (깃헙) 저장소

    배포하기 전에 앱 파일을 저장소에 올려 둡니다. 고친 기록이 남고, 내가 만든 앱이 한곳에 모여 포트폴리오가 돼요.

    1. 새 저장소 만들기 (앱 하나에 저장소 하나)
    2. 파일 올리기 (Add file → Upload files)
    3. 고칠 때도 여기에 다시 올리기
    GitHub 저장소 만들기 ↗
    →
    ▲
    GitHub과 연동해서 배포

    Vercel (버셀)

    GitHub 저장소를 한 번 연결해 두면, 저장소에 새 파일을 올릴 때마다 주소는 그대로 앱만 자동으로 업데이트돼요.

    1. Add New → Project
    2. 배포할 GitHub 저장소 고르기(Import)
    3. Deploy → 주소 확인, 이후는 자동 반영
    Vercel 프로젝트 만들기 ↗

    GitHub 저장소만으로도 GitHub Pages로 배포할 수 있지만, Vercel은 연결 한 번으로 고칠 때마다 바로바로 반영되어 편해요.

    공개 범위 GitHub 저장소를 공개(Public)로 만들면 누구나 파일을 볼 수 있어요. 학생 정보·비밀번호·API 키는 절대 올리지 않습니다. Apps Script와 Firebase의 데이터·권한 설정은 각 서비스에서 따로 관리해요.
